      Ask why

      Answer starts from evidence

      “The weekly ops sync had four action items. Why did only two tasks appear, and not until 10:18?”

      • ● ObservedThe notes were last edited at 10:02:12. At 10:05 the job saved “Waiting for stable meeting notes.” with a retry time of 10:17:12. step 2
      • ◆ StaticNotes are read only once 15 minutes have passed since their last edit; a later edit moves the deadline. src/meetings/automation-runner.ts:38, :77–82
      • ● ObservedSonnet classified all four lines. The planner decided add, add, reuse and exception. steps 4–5
      • ◆ StaticA line whose source identity already has a receipt is reused, never added twice. src/meetings/automation-plan.ts:55–56
      • ◆ StaticA named owner outside the approved recipients fails closed as an issue. src/meetings/automation-plan.ts:67
      • ○ Grouped onlyThe 10:18 run shares the meeting's progress record with the 10:05 run; nothing records one as the cause of the other.

      ◇ Inference Nothing was lost. One item was already a task from an earlier version of these notes, and one names a person outside the approved recipients, so it waits as an issue for the Owner. The delay is the deliberate 15-minute settling time, then the next minute's run.

      ✕ Missing Which earlier version of the notes produced the reused task, and whether the Owner has seen the issue. Next check: the line 3 receipt in exo_write_operations.
